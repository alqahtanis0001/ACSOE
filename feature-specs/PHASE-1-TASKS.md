## Operator additions at approval

Four, folded into the specs and binding:

1. **Spec 22 stands as written.** The SHAP pane is an empty state. Do not design a view for data
   that arrives in Phase 5.
2. **Spec 20's ordering test must be able to fail.** Assert that ordering by `ts` gives a
   *different* sequence than ordering by `cycle_id` would, not merely that the `ts` ordering
   looks right. A fixture that cannot fail is not a fixture.
3. **Spec 19's staleness needs the injected clock.** Reading wall time makes the test a race.
4. **Spec 17's read-only connection is proven by attempting a write**, not by trusting the mode
   string in the URI. A negative test, like spec 14's network guard.
