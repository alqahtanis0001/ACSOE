# Phase 0 — shared task list

Lead-owned. Teammates do not edit this file: **claim by recording the spec number in your own
`context/progress/<agent>.md` before writing code**, exactly as ownership rule 5 says. Three
agents editing one list loses work the same way three agents editing one tracker would.

This build has no `TaskCreate`/`TaskList` tooling, so this file is the shared list and
`SendMessage` is the coordination channel.

## Ordering

**C's 00, 01, 02 come first.** `scripts/verify.py` is what decides whether anything else is
done. A and B start immediately — they simply cannot report a task complete until verify runs.

**B is the critical path.** Fewest tasks, but 11 blocks 12 and 13, and 13 blocks C's
`seed_fixtures_present` criterion and everything Phase 3 tests `safety` against.

## Standing rules for this phase

- Write only inside your own paths. `core/`, `bootstrap.py`, `config/` and `context/*` except
  `progress/` are the lead's — escalate, do not edit.
- Before reporting any task complete, run all four yourself:
  `pytest tests/ -q` · `mypy --strict src/` · `ruff check src/` · `python scripts/verify.py --phase 0`.
  Mid-phase the bar is **no FAIL**; PENDING is expected until the phase closes.
- Write `context/progress/<agent>.md` and append to `docs/build-log/phase-0/<agent>.md`
  **as you work**, not at the end. Every non-trivial problem and its fix, per `script-rules.md`.
- Never guess at trading behaviour. Open question in your progress file, stop that unit,
  escalate.
- Teammates do not commit. The lead commits at task boundaries.
