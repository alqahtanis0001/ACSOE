Sources

Every machine that records. The three kinds carry three different qualities of knowledge and this screen never levels them up into one green light: the master is read from local disk and is current, a server node is read over SSH and is only as fresh as the last check, and a standalone node has no live status at all. A standalone node that has said nothing for a week may be recording perfectly — silence is not evidence, and reporting it as dead is the guess that gets a working recorder switched off.

Coverage

Hours of stream actually captured, per source, per UTC day. Measured from the files: each one's first line to its last, minus the time inside its gap markers, which the recorder wrote itself on reconnect and which are therefore a measurement rather than an estimate. A day the recorder started at 09:00 reads 15h, not 24h, because the other nine hours are missing.

Gaps

Two lists, and only the first is a problem. Uncovered days are days no source recorded: order book and spread for those hours do not exist anywhere and cannot be bought back. Single-source days are days exactly one machine covered — not a failure, but days with no second observation to compare against, so a dropped subscription or a bad feed that day cannot be detected, then or ever.

Import

Both actions stage first. Nothing enters the main archive until it has been copied to a staging directory, parsed from end to end, and copied again with its bytes read back off the destination. A truncated transfer dies in staging: written straight into the archive it would have the right name, be globbed by every tool, and be short — and nothing would report it, because a short JSONL file is a valid JSONL file.

Where two sources cover the same hour, both copies are kept and the overlap is reported with its exact span. That is an independent observation of one market and the difference between the two is the only measurement there is of what a single recorder misses. Quietly keeping one would destroy it.

Pull from a server node

The master opens the connection; the node never opens one to the master and holds no credential for it. Today's file is never pulled — it is open on the node and what would arrive is a prefix of a day.

Check inbox

Merges whatever has been dropped into the inbox folder by any means — a USB stick, a share, a download. This is how a standalone node is collected. Copy whole files, and not the node's file for today.

Create node

Writes a folder ready to copy to another machine: the recorder, the supervisor, a config carrying a fresh source id, and a startup script. Both Python files import nothing from this project, so the folder works on a machine with no checkout — Python plus pip install orjson websockets pyyaml is the whole setup.

No package ever contains a credential for the master. Not a key, not a host, not a URL. A node never initiates a connection here, so there is nothing it needs and therefore nothing on it to steal — which matters because a node is the machine most likely to be compromised.

Server node

A machine the master can reach over SSH. The package carries the master's public key for you to authorise on the node; the private half never leaves this machine and is never read by this process.

Standalone node

The same package without SSH. It records; a person carries the archive over on a disk. The right answer for a laptop on a home connection or a machine behind a NAT nobody wants to open — and the master will correctly report it as having no live status.
