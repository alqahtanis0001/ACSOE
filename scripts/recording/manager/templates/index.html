Sources

What this is for. Every machine that records market data, and what is known about each one. Use it to see that recording is happening, and to spot a machine that has gone quiet.

A source is any machine that records. The master is this machine. A node is any other machine you set up to record. A server node can be checked from here over SSH. A standalone node cannot be checked at all; you collect its files by hand.

How to read it. The Status column says one of four things. They are four different levels of knowledge, not four shades of good and bad.

  • recording This machine, read from its own disk just now.
  • reachable A server node answered the last check. The row says when.
  • not reachable The last check failed. That is about the connection, not the recorder.
  • no live status Nothing can check this machine. This is normal, and it never means dead.
Why silence is never reported as dead

A standalone node has no connection to this machine in either direction. If it has said nothing for a week, it may be recording perfectly. Calling it dead would be a guess, and the guess is wrong in the direction that gets a working recorder switched off. So the screen says what it knows: when files were last brought over, and which days they covered.

A server node is only as fresh as its last check. A check is not done every time the page loads, because it takes seconds per node. The row shows when the check was, so an old reading looks old.

Coverage

What this is for. How many hours of market data each machine actually captured, day by day. Use it to see how much history you hold and where a day came up short.

How to read it. One row per source, one column per UTC day. A cell is hours captured, so 24.0 is a whole day. A dot is a day that source recorded nothing. Darker cells hold more. The last column is the total for that source.

Why the numbers are measured, not assumed

Hours are read from the files themselves: from each file's first line to its last, minus any time inside the recorder's own gap markers. The recorder writes a gap marker whenever it reconnects, so a gap is a measurement rather than an estimate. A day the recorder started at 09:00 reads 15 hours, not 24, because the other nine hours are missing. The first read of a large archive takes a moment; later reads are cached.

Gaps

What this is for. The days that are missing or thin. Use it to find out what has been lost and what is at risk.

How to read it. A gap is a day no machine recorded. Those days are gone for good; the market data for them exists nowhere and cannot be bought or downloaded later. A single-source day was recorded by exactly one machine. It is not lost, but there is no second copy to check it against.

Why a second source matters

Two machines recording the same day give two independent views of one market. The difference between them is the only way to detect a dropped subscription or a bad feed on one of them. A day with one source can never be checked in that way, then or ever. That is why the list of single-source days is shown here even though nothing is missing from them.

Import

What this is for. Bringing files recorded on other machines into this machine's archive. The archive is the folder of recorded files that Coverage and Gaps read. Use this after a node has recorded days you do not yet hold here.

How it works. There are two ways in. Pull fetches files from a server node over SSH. Inbox takes files you copied by hand into the inbox folder, which is how a standalone node is collected. Either way, every file is checked from end to end before it enters the archive. A file that is cut short is refused and left in staging for you to look at.

Why every file is checked first, and why overlaps are kept

A file copied straight into the archive would have the right name and be found by every tool, even if the copy was cut short. Nothing would report it, because a short file is still a valid file. So each file is copied to a staging folder, parsed from end to end, then copied again and read back before it counts.

When two machines cover the same hours, both copies are kept and the overlap is reported with its exact span. Two independent recordings of one market are the only measure there is of what a single recorder misses. Quietly keeping one would destroy that.

Today's file is never pulled from a node. It is still being written to, so what arrived would be part of a day, not a day.

Create node

What this is for. Setting up another machine to record. It writes a folder you copy to that machine. The folder holds the recorder, a supervisor that restarts it, a config with a fresh source id, and a start script. The new machine needs only Python and three packages.

Which kind to pick. Pick standalone unless this machine can already reach the new one over SSH. A standalone node records on its own and you collect its files by hand. A server node can be checked and pulled from here.

Why a package never holds a way back to this machine

No package contains a key, a host name or an address for this machine. A node never connects here, so it needs none, and there is nothing on it to steal. That matters because a node, on someone else's hardware or in someone else's bag, is the machine most likely to be compromised. A server package carries this machine's public key only, for you to authorise on the node. The private half never leaves here.

Standalone node

The usual choice

Records on its own. You carry its files here on a disk and use Import. Right for a laptop, a home connection, or any machine you do not want to open up. This screen will show it as having no live status, which is correct.
